## What I learned building an opinionated and minimal coding agent

**我从构建一个主张鲜明且风格克制的编程代理中所学到的**

[mariozechner.at](https://mariozechner.at/posts/2025-11-30-pi-coding-agent/)

1. OpenClaw 的热潮还未消退，越来越多的人注意到它的底层用到了一个叫做 [pi-mono](https://github.com/badlogic/pi-mono) 的代理引擎。
2. 这篇文章就是是 pi-mono 的作者写的。
3. pi-mono 适配了主流的 AI 模型供应商，同时做了和流行的 Coding Agent 不同的设计，比如：
   - 默认 YOLO 模式
   - 拒绝 MCP
   - 没有 plan mode
   - 没有背景任务
   - 极短的系统提示词
   - 没有子代理
4. 不得不说他的很多理念我都很认同，同时也是我在实践过程中的习惯或者经验。
5. 如果你有计划实现一个 Agent, 或者基于已有的 Agent 来开发，可以考虑下 pi-mono。

## What spec-driven development gets wrong

**规范驱动开发搞错了什么**

[x.com](https://x.com/augmentcode/status/2025993446633492725)

1. 如果你 vibe coding 过，你就知道有一个流派叫做 spec coding。
2. 如果你研究过一些 coding agent，比如 Codex 是没有记忆模块的，我猜想一个可能的原因是代码本身就是全部记忆。
3. 我算是使用 spec-driven 开发的，但我觉得很难定义具体什么是 spec-driven。
4. Spec-driven 最大的问题是计划赶不上变化，在 vibe coding 的过程中，变化发生的更加频繁和容易。
5. 但很多时候文档不仅是写给 AI 看的，更是写给人看的。
6. 实际上我几乎不主动写具体的文档，文档基本都是 AI 生成的。
7. 通过不断的练习，我找到一些经验，但是核心问题还是成本，主要是管理的。这和使用 Agent 的预期肯定是不符的。
8. 依然在探索。
9. BTW Cladue Code [最近的更新](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md#2159)增加了这个能力，我没有研究这个 memory 具体关注的点。
